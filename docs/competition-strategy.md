# 2026 K-Health 미개방 의료데이터 경진대회 — 우승 전략 & 제안서 설계

> 목표: **우승 확률 최대화**. 이 문서는 심사 배점(rubric)에 맞춰 무엇을, 왜,
> 어떻게 할지를 고정한다. 코드 자산(`src/vitals_*.py`)은 이 전략의 실현성 근거다.

---

## 0. 한 줄 요약 (확정 논지)

**"개인 기저선 이탈 기반, 설명가능한 심정지 조기경보로 alarm fatigue를 푼다"** —
경북대병원 활력징후(시계열)로, 정확도 경쟁이 아니라 **오경보(false alarm) 저감 +
설명가능성(XAI)** 을 정면에 내세운다.

**차별화(참신성) 두 축**:
1. **개인화 기저선 이탈** — 병동 고정 임계값(NEWS)이 아니라 **환자 자신의 초기 안정기를
   기저선**으로 삼아 그로부터의 이탈을 탐지. "환자가 곧 자신의 대조군" → 일반화·오경보 동시 공략.
   (합성 데모에서 개인화 편차 피처가 AUPRC 0.76→0.84로 실제 신호를 더함.)
2. **설명가능성(XAI)** — 모든 경보에 "왜 위험한지"(SHAP, 추세·이탈 기반) 근거 제시.

**단순 "예측"이 아니다**: 예측 정확도 경쟁을 우회하고, 개인화·설명·오경보라는 임상 도입
관점의 문제를 푼다.

- **선택 데이터**: [대구] **경북대학교병원 입원환자 활력징후** (`KHTH_PINFO`, `KHTH_VITAL`)
- **개발·검증 데이터**: **MIMIC-IV**(공개 실데이터) — 경북대 case-only 코호트에 없는
  **대조군(비심정지)** 을 제공하므로, 본선 전에 실데이터로 오경보를 정직하게 측정·검증.
- **선택 이유**: 인턴 과제와 정확히 일치, 참신성·시의성·파급성이 모두 강하고, 폐쇄망(안심존)에
  맞는 경량 설계가 가능하며, **실데이터(MIMIC)로 사전 검증이 가능해 실행 리스크가 낮음**.

## 1. 대회 구조와 "우승"의 정의 (2단계 최적화)

| 단계 | 산출물 | 배점 | 통과 조건 |
|------|--------|------|-----------|
| 예선 (~8/14 16:00) | 아이디어 제안서 PDF 30장 | 시의성20·**실현성30·참신성30**·파급성20 | 상위 **15팀** |
| 본선 (~11/6) | 데이터 시각화 결과보고서 + 발표자료 | 수행평가30 + **발표평가70** | 최종 6팀 수상 |

핵심 통찰:
1. **예선은 아이디어 싸움**(코드 제출 없음). 실현성·참신성이 각 30점으로 지배적.
2. **우승은 본선 발표(70점)에서 갈린다.** 결과보고서가 *데이터 시각화* 중심 →
   **시각화 + 명확한 임상 스토리 + 설명가능성**이 곧 점수.
3. **가점·방문 배점은 사실상 공짜 점수.**
   - 예선: 안심존 1회 방문 → **+5점** (상위 15팀 커트라인에서 결정적).
   - 본선 수행평가: 방문 횟수 배점(1회 2점 … **7회+ 10점**).
   - → **예선 기간에 반드시 1회 이상 안심존 방문**(대구 계명대 동산 / 경북대 데이터).
     방문 시 실제 샘플(비식별 5명분)을 보고 제안서 실현성을 끌어올린다.

## 2. 예선 제안서 — rubric 정렬 설계 (30장)

각 심사 항목에 "무엇으로 점수를 딸지"를 못박는다.

### 시의성 (20) — 왜 지금 필요한가
- 원내 심정지 사망률·후유장애의 심각성, **조기경보(EWS)의 임상 도입 실패 원인 = alarm fatigue**.
- 기존 모델은 AUROC 0.85~0.95로 높지만 극단 불균형 탓 **AUPRC가 낮아 오경보 과다** →
  실제 병동에서 무시됨. 이 간극이 공략 지점.

### 실현성 (30) — 진짜 될까
- **이미 도는 파이프라인**을 근거로 제시(합성 데이터 end-to-end 실행, 테스트 통과).
  - `vitals_data.py`(윈도우·환자단위 분할) → `vitals_train.py`(XGBoost vs NEWS) →
    `vitals_explain.py`(SHAP).
- **폐쇄망 적합성**: XGBoost + numpy/pandas/scikit-learn/shap 만으로 완결 →
  안심존 사전신고 패키지 목록이 짧고 명확. 무거운 DL 의존성 없음.
- 실제 데이터 연결 지점(`cohort_from_khth`)까지 코드로 준비 → "설계만 있고 안 되는 제안" 아님.

### 참신성 (30) — 남들과 뭐가 다른가  ★ 최대 차별점
- (1) **정확도가 아니라 오경보 저감을 1차 목표로** 삼는 평가 프레임
  (AUPRC·민감도@고정특이도·**시간당 알람 수/오경보율**).
- (2) **설명가능성 내장**: 모든 경보에 대해 "왜 위험한지"(SHAP top-3, 추세 기반) 제시 →
  임상 신뢰·도입 가능성.
- (3) **case-only 데이터의 역설을 방법론으로 해결**: "심정지 후 사망 환자만 있는(대조군 없는)
  데이터로 어떻게 조기경보와 오경보를 논하는가" → within-patient 라벨링 +
  lead-time 분석 + (개발단계) 외부 대조군 검증. **이 지점이 제안서의 지적 하이라이트.**

### 파급성 (20) — 확장·효과
- 병동 EWS 대체/보완, 타 병원 일반화(외부검증 로드맵), 인턴 트랙의 **ECG/HRV 확장**
  (MIMIC-IV-ECG로 RR interval·QRS·HRV까지) → 상위호환 로드맵 제시.

### 필수 형식 요건 (감점 방지)
- PDF, **30장 이내 엄수**. **선택 데이터셋명 명시** ("경북대학교병원 입원환자 활력징후").
- 외부 자료·논문 **출처 명시**. 팀장 계정으로 최종 제출. 마감 **16:00**(23:59 아님).

## 3. 핵심 방법론 (제안서 & 본선 공통)

```
활력징후 시계열 (맥박·수축기/이완기혈압·체온·SpO2·호흡수, 시점별)
      │
      ▼  슬라이딩 윈도우 (과거 8시간)
피처: vital별 mean/std/min/max/last/slope/delta + shock index, pulse pressure
      + ★ 개인 기저선 이탈({vital}_last_dev/_mean_dev) — 환자 초기 안정기 대비 편차
      │
      ▼  라벨 (within-patient): 향후 1시간 내 심정지 발생 여부
XGBoost (cost-sensitive, scale_pos_weight)   ── 비교군: NEWS(임상표준)
      │
      ▼  평가: AUPRC · AUROC · 민감도@95%특이도 · 오경보율 · 윈도우당 알람 수 · lead-time
      ▼  설명: SHAP 전역 top-k + 경보별 top-3 (추세·이탈 기반 근거)
```

**개발·검증 3단계** (코드는 데이터원과 무관하게 동일 — `cohort_from_*` 어댑터가 흡수):
1. **합성 데이터**(`generate_synthetic_cohort`) — CI·데모, 데이터 없이 end-to-end 실행
2. **MIMIC-IV**(`cohort_from_mimic`) — 실제 ICU 데이터 + **대조군**으로 오경보 정직 측정·검증
3. **경북대**(`cohort_from_khth`) — 본선 안심존, `CARDT` 기준 정밀 라벨(case-only)

**데모 결과(합성, 실데이터 아님):**
- XGBoost vs NEWS: **ROC-AUC ≈ 0.99로 동일**하지만 **AUPRC ≈ 0.78 vs 0.61** →
  "ROC만 보면 안 보이는 오경보 격차"를 그대로 시연.
- **개인화 기저선 이탈 피처 추가 시 AUPRC 0.76 → 0.84** → 개인화가 실제로 신호를 더함(참신성 근거).
- SHAP 상위 = **호흡수·SpO2·맥박의 slope(추세)** → 악화 추세 포착이 조기경보의 본질임을 입증.

## 4. 데이터 명세 (확인됨 · 데이터 설명서 기준)

`KHTH_PINFO` + `KHTH_VITAL`, 조인키 **`PATID` + `INDD`**(입원 단위).

| 테이블 | 핵심 컬럼 | 비고 |
|--------|-----------|------|
| KHTH_PINFO | `PATID`, `AGE`(연령대 범주: 10/20/30…), `SEX`(M/F), `INDD`/`OUDD`(YYYYMMDD), **`CARDT`(심정지발생일시 YYYYMMDDHHMI)**, `DEATHDT` | 환자 1행 |
| KHTH_VITAL | `PATID`, `INDD`, `VSDT`(기록일시, 분단위), **`VS_GBN`**(HR/SBP/DBP/BT/SPO2/RR), `VS_RSLT`(값·문자열) | **long 포맷** |

- **규모**: N=**573명** (2023–2025, 20–80세). 성비 M 65.6% / F 34.4%, 60–80대가 74.5%.
- **정밀 라벨링 가능**: `CARDT`로 **정확한 심정지 시각**을 알 수 있어, 라벨을 실제 이벤트
  기준으로 붙임(레코드 종료 시점 추정 불필요). → `cohort_from_khth`가 CARDT를 사용.
- **관찰창 확보**: "입원 24h 이내 심정지"는 **제외** → 모든 환자에 **≥24h 활력징후 존재**.
- **샘플링**: ~수 분~10분 간격, **불규칙**. → 시간(hour) 버킷으로 집계 후 윈도우(기본 1h,
  `bucket_hours`로 조정). 값은 숫자 변환.
- **long→wide**: `VS_GBN`을 피벗해 vital별 컬럼 생성(코드는 `vitals_data.cohort_from_khth`가 처리).

## 4-1. case-only 대응 (실현성의 급소)

경북대 데이터 = **원내 심정지 후 사망 입원환자 573명만** = **대조군(비심정지) 없음**. 대응:
1. **within-patient 라벨링**: 같은 환자의 안정기(초기) = 음성, `CARDT` 직전 = 양성.
   → 대조군 없이도 "악화 궤적"과 lead-time을 학습·평가 가능.
2. **오경보 지표의 한계 명시 + 보완책**: 순수 특이도는 대조군 부재로 과대평가 위험.
   → (개발) 외부 대조군(eICU/MIMIC 비심정지)로 오경보율 보정, (제안) 병동 전수 데이터
   확장 시 진정한 false-alarm 측정.
3. **lead-time / alarm burden 중심 평가**: 대조군 의존이 낮은 지표(조기경보 확보시간,
   시간당 알람 수)를 전면에.

> 이 한계를 **숨기지 말고 정면으로 다루는 것**이 오히려 참신성·실현성 점수를 올린다.

## 5. 기술 스택 (폐쇄망/안심존 적합)

- **언어/런타임**: Python (대구·광주·대전 모두 제공). R/SPSS도 가용.
- **패키지(사전신고 목록 후보)**: `numpy`, `pandas`, `scikit-learn`, `xgboost`, `shap`,
  `matplotlib`. — 전부 표준·경량. **DL 프레임워크 불요.**
- **주의**: 대구·광주는 **본선 전 사용 패키지·모델 목록 사전 통보 필수**, 전자기기 반입 금지,
  인터넷 불가. → 코드는 외부 다운로드 0 의존으로 유지(현재 설계 충족).

## 6. 본선 계획 (우승은 여기서)

- **결과보고서 = 데이터 시각화 중심**: 악화 궤적 곡선, 위험도 타임라인, SHAP 요약/개별 경보 설명,
  XGBoost vs NEWS의 PR-curve·오경보 비교, lead-time 분포.
- **발표평가(70) 대비**: 임상 스토리(alarm fatigue→오경보 저감→설명가능 경보) 일관성,
  예선↔본선 주제 일관성(배점 항목), 질의응답 대비(case-only 한계·일반화).
- **방문 배점 극대화**: 일정상 **여러 번 방문**(7회+ 목표) + 반출 심의 **1~2주 소요 감안**해
  결과물 반출을 마감 훨씬 전에 신청.

## 7. 리스크 & 대응

| 리스크 | 영향 | 대응 |
|--------|------|------|
| case-only(대조군 없음) | 오경보 측정 신뢰도 | within-patient + 외부검증 + lead-time 지표 |
| 실제 코호트 N 작음 | 과적합·불안정 | 경량 모델·정규화·환자단위 CV, 통계 검정 병기 |
| 안심존 패키지 미비 | 본선 실행 불가 | 사전신고 목록 확정·표준 패키지만 사용, 대전은 반입 신청 |
| 반출 지연(1~2주) | 제출 마감 리스크 | 반출 조기 신청, 결과물 단순화 |
| 30장 초과/형식 오류 | 예선 실격 | 분량·데이터셋명·출처·팀장 제출 체크리스트 |
