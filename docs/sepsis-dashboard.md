# 패혈증 조기경보 대시보드 — 결과와 한계

> KMEDIhub 인턴 트랙. PhysioNet/CinC Challenge 2019(공개) 실데이터로 파이프라인을
> end-to-end 검증하고, 결과를 배포된 화면까지 끌고 간 기록.
> 배포: https://web-ebon-rho-81.vercel.app

## 1. 무엇을 하는 시스템인가

특정 시점에서 **향후 6시간 내 패혈증 발병 확률**을 계산하고, 임계값을 넘으면
경보하며, 그 판단 근거를 제시합니다. 발병 전에 울리므로 조기경보 시스템입니다.

```
활력징후 시계열 (맥박·혈압·체온·SpO2·호흡수)
   ↓ 과거 8시간 슬라이딩 윈도우
   ↓ 통계 피처 + 개인 기저선 이탈 피처
   ↓ cost-sensitive XGBoost
위험도 → 임계값 0.645 초과 시 경보 → SHAP 상위 3개로 근거 제시
```

## 2. 데이터 분할 — 화면에 무엇이 있나

```
원본 파일        20,336명
윈도우 생성 후    19,858명   (633,009 윈도우)
  ├ train       15,886명   506,451 윈도우   ← 학습에만 사용. 화면에 없음
  └ test         3,972명   126,558 윈도우   ← 점수 계산, 지표 측정
       └ 열람       400명    20,272 윈도우   ← 대시보드 (위험도 상위)
```

화면의 400명은 모델이 한 번도 본 적 없는 환자입니다. 그중 **88명(22%)이 실제
패혈증 발병** 환자이고, 발병 시각이 정답 라벨로 함께 표시됩니다.

지표는 잘라내기 전 test 3,972명 전수 기준입니다 — 열람 대상을 줄인 것이 보고되는
숫자를 바꾸지 않습니다.

## 3. 결과

test 3,972명 / 126,558 윈도우 / 양성률 1.19%

| 검출률 | 본 모델 | NEWS | 알람 감소 |
|---|---|---|---|
| 50% | 24.8/100 (특이도 0.755) | 41.3/100 (0.589) | **40%** |
| 70% | 45.8/100 (0.545) | 59.2/100 (0.410) | 23% |
| 90% | 76.3/100 (0.238) | 100.0/100 (0.000) | 24% |

AUPRC 0.027 (기준선 0.0119 대비 2.3배), ROC-AUC 0.679.

두 점수를 같은 민감도로 맞춘 뒤 비교했습니다. NEWS2는 패혈증 스크리닝 도구로도
쓰이므로 같은 라벨에서의 비교가 성립합니다.

90% 지점은 NEWS 특이도가 0 — 전원 알람 상태라 비교가 무의미합니다. 인용하지 마세요.

### 데이터 규모 의존성

| 읽은 환자 | 50% 검출률에서 알람 감소 |
|---|---|
| 4,000명 | 10% |
| 20,336명 (전체) | **40%** |

**"40% 감소"는 전체 데이터 + 50% 검출률 조건에서만 성립합니다.** 부분집합에서는
재현되지 않습니다. 인용 시 조건을 반드시 명시하세요.

## 4. 알아야 할 한계 — 극단 상태에서의 거동

`p005494` 사례에서 발견했습니다. 27시간째에 SpO2 60%(기저선 97.4), 수축기혈압
69(기저선 111.8), 맥박 122→49로 꺾인 상태인데 위험도가 **0.013**이었습니다.
게다가 환자가 악화되는 동안 위험도가 오히려 떨어졌습니다(0.647 → 0.130 → 0.013).

원인은 데이터에 있습니다.

| SpO2 구간 | 6시간 내 발병률 | 전체 대비 |
|---|---|---|
| **70% 미만** | **0.0000** (232건 중 0건) | 0.00x |
| 70~80% | 0.0147 | 1.29x |
| 88~92% | 0.0136 | 1.19x |
| 95% 이상 | 0.0112 | 0.98x |

| 수축기혈압 | 6시간 내 발병률 | 전체 대비 |
|---|---|---|
| **70 미만** | **0.0029** | 0.26x |
| 70~85 | 0.0146 | 1.29x |

SpO2 70% 미만 윈도우 232개 중 발병은 0건입니다. 이미 붕괴한 환자는 발병 시점을
지났거나 다른 원인으로 악화 중이라 **패혈증 발병 확률이 실제로 낮습니다.**

즉 모델은 틀리지 않았습니다. 질문에 정확히 답했을 뿐입니다. 문제는 그 점수를
화면이 "안정"으로 렌더링할 때 생깁니다.

### 대응

`web/src/lib/severity.ts` — 모델과 무관하게 활력징후만 읽는 두 번째 채널을 두고,
붕괴 수준인데 모델이 조용하면 상단에 경고를 띄웁니다.

임계값 조정 과정이 그 자체로 교훈이었습니다.

| 기준 | 경고 발생률 |
|---|---|
| 일반 병동 기준 (SpO2<88, RR>25 등) | **84%** — 소음 |
| 실제 붕괴 수준 (SpO2<80, SBP<75 …) | **7%** |

ICU에서는 호흡수 28이 일상입니다. 일반 병동 임계값을 그대로 쓰면 이 프로젝트가
없애려는 alarm fatigue를 UI가 다시 만듭니다.

## 5. 배포 구조

```
회사 서버 (오프라인)                         Vercel
20,336명 → 학습 → 근거 사전계산     →      JSON 40MB + Next.js
5분 / 4.1GB / xgboost + shap                 파이썬 0 / ML 라이브러리 0
```

| | 사전계산 전 | 후 |
|---|---|---|
| 필요 패키지 | 706 MB | 0 (Node만) |
| 서버 메모리 | 461 MB | 정적 파일 |
| 기동 시간 | 5분 | 없음 |

`libxgboost.so` 226MB(대부분 CUDA 커널)와 `libllvmlite.so` 171MB(shap→numba)가
706MB 중 396MB였습니다. 우리 코드는 94KB인데 그걸 돌리려고 그 둘을 지고 있었습니다.
이미 계산된 숫자를 돌려주는 데는 아무것도 필요 없습니다.

절차는 `docs/deploy.md` 참고.

## 6. 다음에 할 수 있는 것

- **라벨 재정의** — "6시간 내 발병"이 아니라 "악화"(사망·급격한 활력징후 변화)로
  다시 학습하면 4절의 거동이 사라지는지 확인
- **MIMIC-IV 심정지** — 본래 목표. PhysioNet CITI 인증 필요(무료, 2~7일)
- **새 데이터 추론** — 지금은 사전계산만 합니다. 실시간 추론을 붙인다면 xgboost를
  ONNX로 바꾸는 것이 낫습니다(실측: 226MB → 0.5MB 모델 + 56MB 런타임,
  추론 4.9ms → 0.12ms, 오차 3.6e-07)

> 면책: 연구·교육용. 의료기기가 아니며 임상 의사결정에 사용하지 않습니다.
